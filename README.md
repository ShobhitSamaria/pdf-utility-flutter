# PDF Utility

An Android app that turns a photo or an imported PDF page into selectable,
copyable text, and translates that text **on the device** — including a
Google-Lens-style overlay that paints the translation back over the original
document. It also builds new PDFs from captured pages.

Nothing about a document leaves the phone: OCR, language identification and
translation all run through on-device ML Kit models.

## Features

**Extract text**
- Scan with the camera or choose an image from the gallery.
- Import a PDF, pick a page and recognise its text.
- ML Kit text recognition with Latin and bundled Devanagari models; script modes
  are `Auto`, `Latin`, `Devanagari` and an opt-in `Mixed` two-pass mode.
- Sideways pages are detected from ML Kit's line angles and re-read upright.
- The photo shows tappable word boxes; a selection bar offers copy, search,
  share and translate.

**Read the result**
- Three readings of one result — **Image**, **Extracted Text**, **Translate** —
  with selection, search and translation state kept alive across switches.
- Extracted text is grouped into paragraphs in reading order (columns, tables,
  headings), searchable with match stepping, and can be shown back on the photo.

**Translate**
- On-device ML Kit translation into 30 languages, with explicit source
  selection or auto-detection.
- Auto-detection resolves the source script first and distinguishes Hindi from
  Marathi by wording, because ML Kit's language identifier frequently confuses
  the two Devanagari languages.
- Long translations that cannot fit over the image remain available in full in
  the inline translation panel.

**Create PDFs**
- Capture pages with the camera, pick images, or combine pages from an imported
  PDF.
- Reorder/rotate pages, review, then export and share the finished PDF.

**Developer tools (debug builds only)**
- "Show OCR geometry" overlay, OCR benchmark harness, and a translation
  diagnostics screen (model state, self-test, OCR→translation check).

## Requirements

- Flutter with **Dart SDK ^3.12.2** (`flutter --version` should report a matching
  stable release).
- Android SDK with **API 24+** on the device; the app compiles and targets API 36.
- An Android device or emulator. This project contains only the `android/`
  platform folder.
- Network access **once per language pair** so ML Kit can download translation
  models. Recognition and translation then work offline. The Devanagari OCR
  model is bundled in the APK, so Hindi recognition works on first launch.

## Getting started

```bash
flutter pub get
flutter run              # debug build on the connected device
flutter run --release    # release build (signed with the debug key, see below)
```

`android/local.properties` is generated by Flutter and holds machine-specific
SDK paths; it is ignored by Git. If it is missing, Flutter regenerates it.

## Project structure

```
lib/
  app/            composition root helpers, theme, InheritedWidget scope
  ocr/
    domain/       OCR models, layout grouping, search, selection, script detection
    data/         ML Kit engine, image decoding/rotation, orientation pass
    presentation/ coordinate mapper, hit tester, overlay widgets
  translation/
    domain/       languages, requests, region units, script-aware detection
    data/         ML Kit translation engine, language ID, model manager
    presentation/ controller, overlay deck, measured text layout, panels
  pdf/
    domain/       drafts, page layout, renderer/output interfaces
    data/         pdfx renderer, pdf writer, file picker/source, exporter
    presentation/ import, viewer, page selection, capture, review screens
  screens/        home, camera capture, OCR result, selection/extracted text
  diagnostics/    translation and OCR→translation self-tests
  benchmark/      OCR benchmark harness and metrics
test/             unit and widget tests plus image/font fixtures
integration_test/ on-device ML Kit tests (need a device)
test_driver/      driver for `flutter drive` release runs
```

## Testing

```bash
# Unit + widget suite (no device required)
flutter test

# A single file
flutter test test/ocr_document_layout_test.dart

# On-device ML Kit integration tests (real recognizer, real models)
flutter test integration_test -d <device-id>

# Release-mode device run, for R8/AOT-only failures
flutter drive --driver=test_driver/integration_test.dart \
  --target=integration_test/ocr_device_test.dart --release -d <device-id>
```

The unit suite uses fakes for the ML Kit engine and translation service, plus
real-image fixtures under `test/assets/` (EXIF-rotated JPEGs, a Hindi newspaper
page). The Devanagari test font in `test/support/fonts/` ships with its OFL
licence.

## Building

```bash
flutter build apk --release
# → build/app/outputs/flutter-apk/app-release.apk

flutter build apk --debug
# → build/app/outputs/flutter-apk/app-debug.apk
```

The release build currently uses the **debug signing config** (see
`android/app/build.gradle.kts`), which is fine for local installs but must be
replaced with a real keystore before publishing. Put signing credentials in
`android/key.properties` and a keystore outside version control; both patterns
are ignored by `.gitignore`.

A prebuilt release APK is kept locally as `PDF-Utility-Latest.apk`. It is a
generated binary and is ignored by Git.

## Configuration and secrets

- No API keys, tokens or `.env` files are required: all recognition and
  translation is on-device.
- Android's `INTERNET` permission is declared for ML Kit model downloads only.
- `android/local.properties`, `android/key.properties`, keystores, `.env*` files
  and packaged APKs are ignored by Git.
- Debug-only tools are compiled behind `kDebugMode` and are absent from release
  builds.

## Privacy

Document images and recognised text stay on the device. The only network use is
Google ML Kit downloading translation models the first time a language pair is
used.
